# Технический долг / отложенные фичи

Реестр тяжёлых задач, отложенных на будущее. Лёгкие «вины» (CSV-экспорт трекера,
мульти-профили) сделаны в рамках текущей итерации — см. CHANGELOG/коммиты.

Формат записи: **что** · *почему отложено* · ориентировочный объём · зависимости.

## v0.2 — тяжёлые задачи

### 1. Telegram Stars + enforcement лимитов
- **Что:** реальная оплата через Telegram Stars (инвойсы, webhook, идемпотентность
  по `telegram_payment_id`), плюс фактическое применение лимитов из таблицы `config`
  (`free_letters_per_month`, `free_scores_per_day`, `letter_cost_credits`).
- **Почему отложено:** в beta `beta_mode=true` — всё бесплатно, лимиты намеренно не
  enforced. Монетизация включается флагом, торопиться незачем до набора аудитории.
- **Объём:** 3–5 дней (платёжный поток + middleware подсчёта кредитов + тесты на
  идемпотентность).
- **Зависит от:** наличие платящих юзеров (≥50–100 активных).

### 2. Шаблоны сопроводительных — ✅ СДЕЛАНО
- **Что:** сохранять удачные сопроводительные как шаблоны, переиспользовать и
  подставлять переменные (компания/должность).
- **Реализовано:** таблица `letter_templates` (миграция 0006), domain/repo/service
  с IDOR-проверкой через `profiles.user_id`, CRUD API
  (`/api/profiles/{id}/letter-templates`, `/api/letter-templates/{id}`),
  интеграционные тесты. Frontend на экране Letter: список шаблонов с подстановкой
  `{company}`/`{position}` из вакансии (клиентская), сохранение текущего письма как
  шаблона, удаление.

### 3. Источник: Хабр Карьера
- **Что:** второй парсер (`src/sources/habr.py`) под IT-аудиторию.
- **Почему отложено:** hh.ru покрывает ~80% рынка; стабилизируем один источник
  и headless-парсинг прежде чем добавлять второй.
- **Объём:** 2–4 дня (парсер + фикстуры + интеграция в scheduler).
- **Зависит от:** стабильный headless-парсер hh.ru.

### 4. Источник: Авито Работа
- **Что:** третий парсер для рабочих специальностей, общепита, ритейла.
- **Почему отложено:** релевантен только после расширения на не-IT категории (v0.2+).
- **Объём:** 3–5 дней (антибот сложнее, чем у hh.ru).
- **Зависит от:** мульти-категорийность.

### 5. Мульти-категорийные промпты (finance / sales / medical / service)
- **Что:** специализированные промпты скоринга и сопроводительных под топ-категории.
  Механизм выбора по `profile.category` уже есть (`load_prompt(type, category)` с
  фолбэком на `default.md`); нужны сами файлы промптов + eval-датасеты.
- **Почему отложено:** не угадываем — собираем реальные данные от ранних
  пользователей (feedback loop), потом пишем промпты на фактах.
- **Объём:** ~1 день на категорию (+ сбор golden dataset).
- **Зависит от:** feedback loop / реальные пользователи не-IT.

### 6. Feedback loop (бот спрашивает результат после собеса)
- **Что:** бот периодически уточняет статус отклика → данные для улучшения скоринга
  и для killer-фичи отзывов о компаниях.
- **Почему отложено:** требует устойчивого потока откликов в трекере.
- **Объём:** 2–3 дня.
- **Примечание:** частично пересекается с killer-фичей «отзывы о компаниях»
  (верификация через трекер) — проектировать вместе.

### 7. Telegram MainButton для ключевых CTA
- **Что:** нативная нижняя кнопка Telegram (`WebApp.MainButton`) для главных действий
  экранов — «Сгенерировать» (Letter), «Сохранить» (Profile), «Я откликнулся»
  (VacancyDetail). Сейчас эти действия — обычные кнопки внутри контента.
- **Почему отложено:** текущие экранные кнопки работают и понятны; MainButton — это
  полировка нативности, не блокер. Требует аккуратного управления видимостью/состоянием
  loading и привязки к активному экрану (как уже сделано для BackButton).
- **Объём:** 1–2 дня (обёртка над MainButton + хук по аналогии с `useBackButton` +
  интеграция в 3 экрана).
- **Зависит от:** ничего; можно брать в любой момент.

### 8. Редактирование `category_data` в UI
- **Что:** UI для специфичных полей профиля по категориям (для медицины —
  специализация, для общепита — тип кухни и т.д.). Колонка `category_data jsonb`
  в схеме уже есть, бэкенд её принимает.
- **Почему отложено:** в v0.1 только IT; динамические формы под категорию — работа
  фронта, нужна после ввода не-IT промптов.
- **Объём:** 2–3 дня (динамические формы).
- **Зависит от:** мульти-категорийные промпты.

## Killer-фича (отдельный трек) — фаза 1+2 сделаны

### Отзывы о компаниях (об отношении к соискателям)
Не «отзыв сотрудника» как на hh.ru, а оценка качества взаимодействия людей с HR —
чтобы соискатели понимали отношение компании к кандидатам.

Согласованный дизайн:
- ключ компании `company_key` (нормализованное имя/ID), считается в Python —
  единый источник нормализации;
- **верификация только через трекер** — отзыв может оставить тот, у кого есть
  application к этой компании (в любом статусе);
- **5 структурных сигналов + опциональный текст** (не свободный отзыв),
  взвешенный «respect-score» 0–100;
- **без жёсткой модерации в v1** (осознанное решение: приложение народное —
  чем честнее, даже с матами, тем откровеннее отзыв; текст показываем сразу,
  без pending/approved-гейтинга).

**Сделано (backend + frontend):**
- backend core: таблица `company_reviews` (миграция 0005), domain/repo/service,
  верификация, агрегат, бейдж в ленте; 22 интеграционных/unit-теста;
- frontend: бейдж 🤝 на `VacancyCard`, карточка + форма (5 пикеров + текст) на
  `VacancyDetail`, гейт по `can_review`;
- **post-hoc модерация (фаза 3, частично):** кнопка «пожаловаться» на отзыв,
  таблица `company_review_reports` + `company_reviews.is_hidden` (миграция 0007),
  идемпотентные жалобы (unique `review_id`+`user_id`), авто-скрытие при
  `REPORT_HIDE_THRESHOLD=3` (скрытый отзыв исчезает из публичных списков/агрегата,
  но автор видит свой); интеграционные тесты.

**Осталось (фаза 3, отложено):** tracker-триггеры (бот предлагает оставить отзыв
после смены статуса), cold-start сидинг отзывов.

### Tech-debt по этой фиче (мелочи, не блокеры)

#### a) Пагинация списка отзывов на `VacancyDetail` — ✅ СДЕЛАНО
- Клиентская пагинация: показываем первые 3 отзыва, остальные — по кнопке
  «Показать ещё N». Backend `list_for_key` уже поддерживает `limit`/`offset` —
  при росте базы можно перейти на серверную/infinite query без изменения контракта.

#### b) Лишний запрос на `VacancyDetail`
- **Что:** `CompanyReviewSection` дёргает свой `company-review` query независимо от
  уже идущих `vacancy`/`feed`-запросов экрана → +1 HTTP на каждое открытие детали.
- **Почему отложено:** не критично (один лёгкий GET, кэшируется TanStack Query);
  объединять имеет смысл только если профилировщик покажет проблему.
- **Объём:** ~0.5 дня (либо вшить summary в `GET /vacancies/{id}`, либо префетч).

## v0.3 — Public Release (продуктовые куски, в roadmap, не начаты)

### 9. Referral-система
- **Что:** «приведи друга → получи кредиты». Реферальные коды/ссылки (через
  Telegram `start_param`), начисление кредитов обоим при первом действии приглашённого.
- **Почему отложено:** монетизация и кредиты пока не enforced (`beta_mode`); реферал
  бессмысленен без ценности кредита.
- **Объём:** 2–3 дня (коды + атрибуция + защита от накрутки).
- **Зависит от:** Telegram Stars / enforcement лимитов (п.1).

### 10. PWA / оффлайн-режим
- **Что:** манифест + service worker, кэш ленты/деталей для просмотра офлайн.
- **Почему отложено:** MiniApp работает только внутри Telegram-клиента (онлайн);
  офлайн — приятный бонус, не закрывает боль.
- **Объём:** 2–3 дня (Workbox + аккуратная инвалидизация кэша).

### 11. TG-каналы вакансий как источник
- **Что:** парсинг вакансий из публичных Telegram-каналов (новый `Source`-парсер).
- **Почему отложено:** разнородный неструктурированный текст → нужен LLM-экстрактор
  полей; дороже и шумнее, чем hh.ru.
- **Объём:** 3–5 дней (чтение каналов + LLM-парсинг в структуру + дедуп).
- **Зависит от:** стабильный мульти-источник pipeline.

### 12. Аналитика использования для команды
- **Что:** дашборд по таблице `events` (что юзеры делают: просмотры, скоринги,
  письма, отклики) — для продуктовых решений.
- **Почему отложено:** events пишутся, но при текущей аудитории смотреть нечего;
  нужен после набора юзеров.
- **Объём:** 2–4 дня (агрегаты + простой дашборд/экспорт).

### 13. Английский интерфейс (i18n)
- **Что:** вынос строк в словари, переключатель языка; сейчас RU захардкожен.
- **Почему отложено:** ЦА v0.1–0.3 — РФ; англ. нужен только при выходе за рынок.
- **Объём:** 2–3 дня (i18n-обвязка + перевод строк).

## v0.4+ — Идеи на будущее (горизонт, без обязательств)

Не план, а пул идей из roadmap. Брать только при явном продуктовом сигнале.

- **Fine-tuning модели скоринга** на собственных данных (реакции + фидбек) —
  после накопления размеченного датасета.
- **Голосовой ввод заметок в трекере** — speech-to-text при добавлении заметки.
- **Нативное мобильное приложение** (помимо MiniApp) — если упрёмся в ограничения
  Telegram WebApp.
- **Командные тарифы** для рекрутинговых агентств — мультиюзер/биллинг на команду.
